# metodics.md — Универсальный скелет карточной военной стратегии

> Методика создания пошаговых карточных стратегий о реальных войнах.
> Применена впервые на «Civil War: Blue & Gray», переиспользуема для любой войны.

---

## 1. Принцип

Любая война = набор данных. Меняем данные — получаем новую игру.
Движок, UI, AI, механика боя — **одни и те же**. Меняется только контент:

```
[Движок Godot] + [JSON-данные конкретной войны] = Готовая игра
```

## 2. Пайплайн создания игры (пошагово)

### Шаг 1: Исследование войны (1–2 дня)

**Источники:** Wikipedia (RU+EN), исторические справочники, документальные фильмы.

**Собрать:**
- [ ] Период войны (даты начала и конца)
- [ ] Стороны конфликта (2 стороны, иногда 3+)
- [ ] Ключевые командующие (ФИО, звания, фото/портреты)
- [ ] Типы войск (пехота, кавалерия, артиллерия, флот, авиация, etc.)
- [ ] Реальные номера подразделений с описанием чем знамениты
- [ ] Ключевые сражения (дата, место, исход, потери)
- [ ] Техника (корабли, танки, самолёты — что было)
- [ ] Особые события (предательства, героизм, катастрофы)
- [ ] Географию (карта, территории, ключевые точки)

- [ ] Культурный контекст (музыка, униформа, символика)

**Результат:** папка `research/` с сырыми заметками.

### Шаг 2: Проектирование систем

#### 2.1 Ресурсы

Определить 3–4 ресурса для конкретной войны:

| Война | Ресурс 1 | Ресурс 2 | Ресурс 3 | Ресурс 4 |
|-------|----------|----------|----------|----------|
| Гражданская война США | Люди | Деньги | Снабжение | Мораль |
| WWII | Промышленность | Нефть | Люди | Наука |
| Наполеоновские войны | Рекруты | Казна | Провиант | Репутация |
| WWI | Людской ресурс | Промышленность | Снабжение | Настроение |

#### 2.2 Мораль / Настроение

Всегда нужна «мягкая» шкала (-20 .. +20), отражающая волю к борьбе:

- Верхний порог: бонусы (+карты, +сила)
- Нижний порог: штрафы (-видимость, дезертирство)
- Абсолютный низ: автопоражение (революция, капитуляция, мятеж)

Каскадные эффекты привязать к реальным событиям:
- WWII: бунты в Италии 1943, попытка убийства Гитлера 1944
- Наполеон: бегство из России 1812, Ватерлоо 1815

#### 2.3 Ход

Один ход = фиксированный отрезок времени:

| Война | Масштаб хода | Max ходов |
|-------|-------------|-----------|
| Гражданская война США | 1 месяц | ~49 |
| WWII | 1 месяц | ~72 |
| Наполеоновские войны | 1 сезон | ~80 |
| WWI | 1 месяц | ~52 |

Фазы хода (универсальные):
1. Ресурсы
2. Розыгрыш карт
3. Перемещение
4. Бой
5. События
6. Конец хода

### Шаг 3: База данных карт

#### 3.1 Типы карт

Всегда **две колоды:**

| Колода | Содержимое |
|--------|-----------|
| **Юниты** | Реальные подразделения с номерами, корабли, техника |
| **Ситуации** | События, приказы, командующие, спецдействия |

#### 3.2 Формат юнита (JSON, универсальный)

```json
{
  "id": "<side>_<type>_<unique>",
  "name_en": "...",
  "name_ru": "...",
  "side": "side_a | side_b",
  "type": "infantry | cavalry | artillery | ship | tank | aircraft | ...",
  "rarity": "common | uncommon | rare | legendary",
  "attack": 1–8,
  "defense": 1–8,
  "hp": 1–10,
  "cost": 1–7,
  "description_en": "...",
  "description_ru": "...",
  "flavor_en": "...",
  "flavor_ru": "...",
  "tags": ["tag1", "tag2"],
  "linked_events": ["EVENT_ID"]
}
```

#### 3.3 Формат ситуационной карты с привязкой (убийственные карты)

```json
{
  "id": "EVENT_<NAME>",
  "name_en": "...",
  "name_ru": "...",
  "type": "situation",
  "side": "side_a",
  "cost": 1–5,
  "effect": "INSTANT_DESTROY | BUFF | DEBUFF | SWAP | HEAL | ...",
  "target_required": true,
  "target_ids": ["exact_unit_id"],
  "historical_date": "YYYY-MM-DD",
  "one_time_use": true,
  "description_en": "...",
  "description_ru": "..."
}
```

#### 3.4 Алгоритм поиска «связей» между событиями

Для каждого реального события войны задать вопросы:

1. **Кто это сделал?** → привязать к конкретному юниту/командующему
2. **С кем это произошло?** → привязать к жертве
3. **Когда?** → дата, ограничение по ходу
4. **Каков был результат?** → эффект в игре (уничтожение, бонус, штраф)
5. **Можно ли это было предотвратить?** → контр-карта

**Примеры связей из разных войн:**

| Война | Событие | Карта-цель | Эффект |
|-------|---------|-----------|--------|
| Гр. война США | Торпеда Кушинга | CSS Albemarle | Мгновенное уничтожение |
| WWII | Перл-Харбор | Линкоры США в порту | Массированный удар, -HP |
| WWII | Дамбастерс | Плотины Рура | Уничтожение промышленности |
| Наполеон | «Сто дней» | Наполеон возвращается | +мораль, но риск катастрофы |
| WWI | Рождественское перемирие | Обе стороны | Бой отменяется на 1 ход |

### Шаг 4: Карта

#### 4.1 Выбор территорий

Взять реальную карту театра военных действий. Разделить на:
- **Регионы/области** — крупные единицы контроля
- **Ключевые точки** — столицы, порты, ж/д узлы, перевалы

#### 4.2 Модификаторы местности

Всегда определить 5–7 типов местности:

| Тип | ATK | DEF | Движение | Пример |
|-----|-----|-----|----------|--------|
| Равнина | +0 | +0 | x1.0 | Степь, пустыня |
| Холмы | -1 | +2 | x0.8 | Аппалачи, Арденны |
| Лес | -1 | +1 | x0.7 | Шенандоа, Арденны |
| Река | -2 | +3 | x0.5 | Миссисипи, Рейн |
| Город | -2 | +4 | x0.5 | Сталинград, Ричмонд |
| Горы | -3 | +3 | x0.3 | Альпы, Кавказ |
| Болото | -2 | +1 | x0.4 | Миссисипи дельта |

#### 4.3 Особые территории

Для каждой войны найти 5–10 особых точек с уникальными бонусами:

| Война | Территория | Бонус |
|-------|-----------|-------|
| Гр. война США | Долина Шенандоа | +2 снабжение/ход |
| WWII | Суэцкий канал | +3 деньги/ход, морской путь |
| Наполеон | Москва | Контроль = +5 мораль, но труднодержать |
| WWI | Проливы Дарданеллы | Морской путь, контроль = логистика |

### Шаг 5: Командующие

Для каждой войны определить 10–15 командующих на сторону:

| Поле | Описание |
|------|----------|
| ID | Уникальный |
| Имя (RU/EN) | Реальное |
| Звание | Историческое |
| Эффект | Модификатор боя/морали/ресурсов |
| Стоимость | 0–6 |
| Риск | Побочный эффект (Джексон: гений но может погибнуть от своих) |

**Шаблон эффекта командующего:**
- Бонус + штраф (баланс)
- Привязка к конкретным юнитам (Чемберлен → 20-й Мэн)
- Привязка к конкретной территории (Шерман → Джорджия)

### Шаг 6: Боевая система

Универсальная формула:

```
урон = (ATK_атакующего + d6) - DEF_обороны
урон = max(урон, 0)
HP -= урон
если HP <= 0 → юнит уничтожен
если оборона выжила → контратака
```

**Модификаторы (подбираются под войну):**

| Война | Типы юнитов | Ключевая асимметрия |
|-------|------------|-------------------|
| Гр. война США | Пехота/Кав/Арт/Флот | Кавалерия бьёт артиллерию (+3) |
| WWII | Пехота/Танки/Арт/Авиация/Флот | Авиация: может бить любую территорию |
| Наполеон | Пехота/Кавалерия/Артиллерия | Кавалерия: бонус при атаке с фланга |
| WWI | Пехота/Артиллерия/Флот/Авиация | Траншеи: огромный DEF, артиллерия его пробивает |

### Шаг 7: Условия победы

Всегда **4 базовых:**

1. **Захват столицы** — удержание N ходов
2. **Моральный крах** противника (-20)
3. **Историческая капитуляция** — привязка к реальным событиям
4. **Истечение времени** — победа по очкам

+ **Сценарии** (по годам/кампаниям) с уникальными целями.

### Шаг 8: Звук и музыка

#### Патефон/Jukebox

Универсальная система музыкального проигрывателя:
- Категории треков (подбираются под эпоху)
- Привязка к сторонам (Север/Юг, Союзники/Ось и т.д.)
- Автоматическая музыка по контексту (меню/карта/бой/победа/поражение)
- Ручное управление через интерфейс патефона

#### SFX (универсальный набор)

```
card_play, card_draw, battle_start, battle_hit, battle_destroy,
march, morale_up, morale_down, victory, defeat, button_click
```

Доп. эффекты под эпоху (патефон: треск винила, завод; WWII: сирены, танки).

### Шаг 9: Локализация

CSV формат: `key,ru,en`

Покрыть:
- Названия всех карт (юниты, ситуации, командующие)
- Элементы UI
- Статусы морали
- Уведомления событий
- Описания территорий

### Шаг 10: AI

Универсальный AI с весами:

```
оценка_хода = 
  w1 * (территории_мои - территории_врага)
+ w2 * (мораль_моя - мораль_врага)  
+ w3 * (ресурсы_мои - ресурсы_враги)
+ w4 * (сила_армии_моей - сила_армии_врага)
+ w5 * (бонус_от_командующих)
```

Веса зависят от «стратегии»:
- Консервативная: w1 высокий, w4 низкий
- Агрессивная: w4 высокий, w1 низкий
- Баланс: равные

## 6. Философия подхода

1. **Реальные номера** — каждый юнит имеет исторический номер подразделения. Никаких «пехота №1».
2. **Связи событий** — исторические события привязаны к конкретным юнитам. Это создаёт «охоту» за контр-картами.
3. **Мораль как предел** — нельзя бесконечно призывать/воевать. Население восстаёт.
4. **Патефон** — музыка эпохи часть опыта. Не фоновый шум, а интерактивный элемент.
5. **Двуязычность** — RU + EN из коробки. Все исторические названия дублируются.
6. **Данные отделены от кода** — JSON-файлы. Новая война = новые JSON, тот же движок.
7. **Одна кампания** — игра всегда начинается с первого дня войны. Не бывает «начать с 1943».
8. **События по ходу** — исторические события триггерятся по номеру хода, а не «выбираются».

## 7. Пайплайн генерации графики (подтверждён на практике)

### 7.1 Инструмент: Pollinations.ai

**Бесплатный**, без регистрации, работает через URL:

```
https://image.pollinations.ai/prompt/{PROMPT}?width=512&height=768&nologo=true&seed={SEED}
```

- Скачивать через `curl.exe -s -o output.png "{URL}" --max-time 180`
- **Rate limit:** при массовых запросах (>50 подряд без пауз) — возвращает 1KB файлы-ошибки
- **Решение:** паузы 12-15 секунд между запросами, или батчи по 20-30 карт

### 7.2 Стиль-промпт (универсальный, менять только эпоху)

```
19th century engraving style, Harper's Weekly illustration,
detailed cross-hatching, fine linework, sepia tones,
historical print, vintage woodcut engraving
```

Для WWII: заменить на `World War II era, wartime illustration, military lithograph`
Для Наполеона: `Napoleonic era, early 19th century military illustration`
Для WWI: `World War I era, 1910s wartime illustration`

### 7.3 Цветовое кодирование (КРИТИЧНО)

**Каждая карта должна быть визуально привязана к стороне:**

| Сторона | Цвет | Промпт-добавка |
|---------|------|---------------|
| Сторона A | Синий | `sepia tones with subtle blue color tinting, blue color dominant throughout image` |
| Сторона B | Красный | `sepia tones with subtle red color tinting, red color dominant throughout image` |
| Нейтральные | Сепия | `warm brown tinting, no dominant blue or red` |

Игрок должен с первого взгляда отличать свои карты от чужих в руке.

### 7.4 Шаблоны промптов по типам

**Пехота:**
```
{STYLE}, {REGIMENT NAME} {ACTION}, {SIDE} soldiers in {UNIFORM},
{COLOR_TINT}, dramatic composition, card game illustration
```

**Кавалерия:**
```
{STYLE}, {REGIMENT NAME} cavalry {ACTION}, mounted soldiers with {WEAPONS},
{COLOR_TINT}, dynamic action, card game illustration
```

**Артиллерия:**
```
{STYLE}, {BATTERY NAME} artillery {SCENE}, cannons firing, smoke and fire,
{COLOR_TINT}, dramatic, card game illustration
```

**Флот:**
```
{STYLE}, {SHIP NAME} {SHIP TYPE}, {NAVAL SCENE},
{COLOR_TINT}, maritime engraving, card game illustration
```

**Командующие (портреты):**
```
{STYLE}, portrait of {NAME}, {RANK}, {UNIFORM DETAILS},
{DISTINGUISHING FEATURE}, formal portrait, {COLOR_TINT}, card game illustration
```

**Ситуационные карты:**
```
{STYLE}, {EVENT DESCRIPTION}, {SCENE},
{COLOR_TINT or NEUTRAL}, dramatic scene, card game illustration
```

### 7.5 Процесс генерации

1. **Тестовая партия** (3-5 карт) → проверить стиль, единообразие, цвета
2. **Создать gen_batch.js** — Node.js скрипт, читает JSON → генерирует curl-команды
3. **Запустить gen_all.bat** — массовая генерация (без пауз, быстро но ~40% фейлов)
4. **Запустить gen_slow.ps1** — перегенерация ошибок с паузами 12 сек (надёжно)
5. **Проверить:** файлы <10KB = ошибка, перегенерить

### 7.6 Генераторный скрипт (шаблон для переиспользования)

```javascript
// gen_batch.js — универсальный шаблон
const fs = require('fs');
const cards = JSON.parse(fs.readFileSync('data/cards/units_side_a.json', 'utf8'));
const base = 'https://image.pollinations.ai/prompt/';
const style = '19th century engraving...'; // менять под эпоху
const cmds = [];
cards.forEach((card, i) => {
    const tint = card.side === 'side_a' ? 'blue tint' : 'red tint';
    const prompt = `${style}, ${card.name_en}, ${card.description_en}, ${tint}`;
    const url = `${base}${encodeURIComponent(prompt)}?width=512&height=768&nologo=true&seed=${i}`;
    cmds.push(`curl.exe -s -o "assets/sprites/cards/${card.id}.png" "${url}" --max-time 180`);
});
fs.writeFileSync('gen_all.bat', cmds.join('\r\n'));
```

### 7.7 Рамки по редкости

Генерировать отдельно, 4 штуки:

| Редкость | Цвет | Промпт |
|----------|------|--------|
| Common | Серая | `simple gray frame with thin decorative lines` |
| Uncommon | Зелёная | `elegant green frame with leaf scrollwork` |
| Rare | Синяя | `rich blue frame with military motifs` |
| Legendary | Золотая | `ornate gold frame with eagle and laurel wreath` |

### 7.8 Карта территории

**Не** генерировать абстрактную карту — AI делает «из XIII века».

Правильный подход:
1. Создать SVG-схему с полигонами территорий (текстовый файл, точные координаты)
2. В Godot — рисовать территории программно (PanelContainer с цветами)
3. Фон карты — либо сгенеренная гравюра, либо чистый пергаментный цвет `#f4e8c1`

### 7.9 Шрифты

Исторические шрифты под эпоху:

| Эпоха | Заголовки | Тело текста | Где брать |
|-------|----------|------------|-----------|
| XIX век (Гр. война) | Cinzel (Google Fonts) | Crimson Text (Google Fonts) | google.com/fonts |
| WWII | Impact / Bebas Neue | Roboto Slab | google.com/fonts |
| Наполеон | Playfair Display | EB Garamond | google.com/fonts |
| WWI | Spectral | Libre Baskerville | google.com/fonts |

Скачивать TTF из Google Fonts → положить в `assets/fonts/` → зарегистрировать в Godot.

## 8. Отрисовка карт (подтверждённый подход)

### 8.1 НЕ встраивать статы в картинку

Статы (ATK/DEF/HP/Cost) рисуются **программно** через `_draw()` в Godot.

Причины:
- Статы меняются (баффы, дебаффы, ранения)
- Баланс меняется — не перегенерировать же картинки
- Локализация — имена на разных языках

### 8.2 card_widget.gd — архитектура

```
┌─────────────────────┐
│ [Имя карты]         │ ← Label, белый на тёмном
│ [тип] 🔫 пехота     │ ← маленький серый
├─────────────────────┤ ← цветная полоса (синяя/красная)
│                     │
│   [ИЛЛЮСТРАЦИЯ]     │ ← PNG из генератора
│   (портрет карты)   │
│                     │
├─────────────────────┤ ← цветная полоса
│ ATK DEF HP  COST    │ ← Labels
│  3   4   4   3      │ ← Цвета: красн/син/зел/жёлт
│ ██████              │ ← Полоска HP если ранен
└─────────────────────┘
```

- Фон: синий (сторона A) или красный (сторона B)
- Рамка: цвет по редкости (серая/зелёная/синяя/золотая)
- Левая и правая кромки: толстая полоса цвета стороны (4px)
- ⚡ = карта имеет linked_events
- ★ = командующий

### 8.3 Карта игровая (map_controller.gd)

Территории = PanelContainer с цветами:
- Синий = Сторона A
- Красный = Сторона B
- Серый = Нейтральная
- Жёлтый = подсвечена (выделена)
- ★ = столица, ⚓ = порт, 🚂 = ж/д
- Маркеры войск: количество + цвет по стороне

## 9. Отрисовка карт (подтверждённый подход)

*(дубль раздела для полноты — вся визуальная система)*

### Карта = программа, не картинка

Территории рисуются кодом, не генерируются AI. AI генерирует только:
- Иллюстрации карт (юниты, ситуации, командующие)
- Рамки по редкости (4 шт)
- Фон карты (1 шт — пергамент)

Карта территорий = SVG-схема + программная отрисовка в Godot.

## 10. Тестирование

### Структура тестов

```
tests/
├── test_base.gd          — базовый класс с assert
├── test_runner.gd        — запускает все тесты
├── test_card_database.gd — загрузка JSON, поиск, фильтрация
├── test_battle_resolver.gd — формулы боя, типы, местность
├── test_morale_system.gd   — диапазоны, каскады, столицы
└── test_turn_manager.gd    — фазы хода, сериализация
```

### Что тестировать обязательно

1. **Загрузка данных** — все JSON читаются, все карты на месте
2. **Статы в диапазоне** — ATK 1-8, DEF 1-8, HP 1-10, Cost 0-7
3. **Бой** — урон не отрицательный, типы дают бонусы
4. **Мораль** — капы -20/+20, статусы правильные
5. **Ход** — фазы по порядку, сериализация/десериализация
6. **Карта** — территории загрузились, связи корректны

### Запуск

В Godot: добавить test_runner.gd как автозагрузку или запустить сцену.
